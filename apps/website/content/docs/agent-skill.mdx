medmark ships an [agent skill](https://github.com/brionmario/medmark/tree/main/skills/medmark) that teaches coding
agents (Claude Code, Codex, Cursor, Copilot) how to run the CLI and put the generated Markdown online.

Once it's installed, this is the whole workflow:

> Convert my Medium export to Markdown and get it hosted.

The agent runs `npx medmark`, asks who the blog belongs to, builds a [Next.js](https://nextjs.org) blog from the output
with your name and details on it, previews it locally, and walks you through deploying to Vercel, Netlify, Cloudflare
Pages or GitHub Pages.

## Install

<Tabs items={['skills CLI', 'Claude Code plugin', 'Manual']}>

<Tab value="skills CLI">

Works across Claude Code, Codex, Cursor and other agents:

```bash
npx skills add brionmario/medmark
```

</Tab>

<Tab value="Claude Code plugin">

```bash
/plugin marketplace add brionmario/medmark
```

```bash
/plugin install medmark@medmark
```

<Tab value="Manual">

Copy the skill folder into your agent's skills directory:

```bash
git clone https://github.com/brionmario/medmark.git /tmp/medmark
cp -R /tmp/medmark/skills/medmark ~/.claude/skills/medmark
```

## What the skill does

<Steps>

<Step>

### Converts your archive

It scaffolds the working folders with `npx medmark init`, tells you where to unzip the Medium archive, and runs the
conversion. Requesting the archive from Medium is still yours to do. The agent can't download it for you.

</Step>

<Step>

### Makes it your blog, not an export

Before building anything it asks whose blog this is. Paste a LinkedIn profile, type the details, or give just a name and
a couple of links. Your name, role, bio and links go into `site.config.ts`, and every section that has nothing to say
hides itself. It won't invent a career you don't have.

It also asks which of the four palettes you want (clay, ink, forest or plum) and the dev server has a `/themes` page
that shows them side by side, so the look is a choice you make by eye rather than a default you inherit.

</Step>

<Step>

### Builds a site from the output

The skill carries a Next.js 16 starter: App Router, TypeScript, Tailwind v4, statically exported. It reads medmark's
folder-per-slug output straight from `content/posts/`: posts grouped by year, post pages with tags and syntax
highlighting, tag pages, an about page, RSS, sitemap, OG tags, and a light/dark toggle. Markdown is rendered with raw
HTML allowed, so Medium's figures and embeds survive.

</Step>

<Step>

### Previews and deploys

`npm run dev` for a local preview, `npm run build` for static output in `out/`, then any static host. The skill covers
Vercel, Netlify, Cloudflare Pages and GitHub Pages, and it confirms with you before running a deploy.

</Step>

</Steps>

## Keeping posts in sync

Re-export from Medium, re-run `npx medmark`, copy the output over `content/posts/` again and redeploy. Posts you deleted
on Medium stay until you clear the folder first.

## Without an agent

The starter is a plain Next.js project. You can use it on its own:

```bash
git clone https://github.com/brionmario/medmark.git /tmp/medmark
cp -R /tmp/medmark/skills/medmark/scaffold my-blog
cd my-blog
cp -R ../medmark/output/. content/posts/
npm install
npm run dev
```

Fill in `site.config.ts`, then deploy `out/` anywhere.
